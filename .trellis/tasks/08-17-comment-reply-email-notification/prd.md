# 评论被回复邮件通知

## Goal

当站点内某条评论收到嵌套回复时，通过邮件告知原评论者“你的评论被回复了”，补齐现有评论通知矩阵。

## Background

- 现有评论邮件通知已覆盖评论状态变化和管理员新评论提醒。
- 本次新增的业务受众是被直接回复的父评论作者。

## Confirmed Facts

- 新回复必须指向同一文章/页面下已 `approved` 的直接父评论。
- 游客回复创建为 `pending`，会获得撤回 capability；已登录用户回复创建为 `approved`并立即公开。
- 父评论作者可为游客（`guestEmail`）或已登录用户（本地用户可空 `ssoId`）。
- 现有 H 通知服务已实现模板请求、幂等键、有限重试、脱敏日志和开关/token 边界。

## Requirements

- 带 `parentId` 的新评论符合最终产品规则时，向父评论作者发送“你的评论被回复了”邮件。
- 仅在新回复已公开时发送：已登录用户的 `approved` 回复创建成功后立即发送；游客 `pending` 回复不发送，在管理员将其改为 `approved` 后尝试发送。
- 被 `rejected` 的回复不发送被回复通知；后续 `rejected -> approved` 属于首次公开，应发送。
- 仅通知直接父评论作者，不向祖先评论作者扩散。
- 回复自己的评论时不发送。
- 父评论为已登录用户时，通过 H `kind: "user"` 和本地 `ssoId` 发送；`ssoId` 缺失/非正数时跳过，不回退到账户邮箱。
- 父评论为游客时，通过 H `kind: "email"` 和父评论 `guestEmail` 发送。
- 自回复判定：登录身份之间比较本地 `authorId`；游客身份之间比较去空格并转小写的邮箱；登录用户回复游客父评论时，比较当前登录邮箱与父评论游客邮箱。
- 继续使用现有 H 通知服务、数据库 mail token、幂等、有限重试和脱敏日志边界。
- 新邮件的 HTML 模板与变量契约存放在仓库，由人工发布到 H。
- 新增 H 模板键 `applog-comment-reply`，建议主题为“你的评论收到了新回复”。
- `applog-comment-reply` 变量为父评论作者显示名、回复者显示名、目标标题/类型、父评论纯文本摘要、新回复纯文本摘要和新回复公开锚点链接。
- 两段摘要分别限制为 160 个 Unicode 码点，不向模板传递邮箱、IP、User-Agent、token 或原始 HTML。

## Acceptance Criteria

- [ ] 符合规则的嵌套回复会尝试通知被回复的父评论作者。
- [ ] 顶层评论不产生“评论被回复”通知。
- [ ] 已登录用户的公开回复创建后通知；游客待审回复转为 `approved` 后使用稳定幂等键尝试通知，重复批准不会形成新的逻辑邮件事件。
- [ ] 不通知被拒绝的回复、顶层评论、祖先评论作者或回复者本人。
- [ ] 父评论登录作者使用 `ssoId`，父评论游客作者使用 `guestEmail`，登录作者无有效 `ssoId` 时脱敏跳过。
- [ ] 登录/游客/身份切换三种自回复判定都有测试，不向回复者本人发送。
- [ ] 通知失败不回滚已成功的回复创建或审核状态变更。
- [ ] 收件人、触发时机、自回复与审核行为有可执行且有测试的规则。
- [ ] 服务端使用 `applog-comment-reply` 及约定的最少变量，仓库包含对应 HTML 与人工发布文档更新。

## Out of Scope

- 重新设计 H 通知客户端、mail token 配置界面或持久化 outbox。
