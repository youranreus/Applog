# WakaTime Landing 数据能力调研

## Goal

调研 WakaTime 截至 2026-08-21 通过官方 API、官方公开分享接口或官方插件生态可读取的数据，重点识别可用于呈现 AI 辅助开发方式、工具偏好与编码节奏的指标，为 Applog Landing 后续设计提供可执行的数据与可视化建议。

用户价值：访客不只看到“写了多久代码”，还能够理解站点作者近期在做什么、怎样使用 AI 工具，以及长期创作节奏，同时避免暴露敏感的项目名、文件名或代码内容。

## Background

- Applog 已在 Landing 展示最近文章、Duolingo 学习统计和 Garmin 运动统计；现有集成倾向于使用后端归一化的公开白名单 DTO，并允许第三方不可用时整段降级隐藏。
- 仓库已有 `docs/research/` 作为研究文档目录。
- 本任务只做资料调研与展示方案建议，不直接实现 WakaTime 集成或修改 Landing 产品代码。

## Requirements

- R1：以 WakaTime 官方文档、官方 API schema、官方 changelog / help / 插件资料等一手来源为主，明确区分 API 已确认能力、需特定套餐或权限的能力，以及无法由 WakaTime 直接提供的推导指标。
- R2：按 API 资源列出可读取字段、时间粒度/范围、权限或隐私约束、Landing 价值及推荐展示形式。
- R3：重点覆盖 AI 方向，包括 AI 编程工具、IDE/编辑器、模型或代理、插件类别、AI 辅助时长/占比等；若官方 API 不能提供某项，必须明确标注而非推测。
- R4：区分“原始指标”“可安全聚合的派生指标”“不建议公开的数据”，并说明隐私风险。
- R5：给出适合当前 Applog Landing 的信息架构推荐、指标优先级及富有创意但可实现的展示形式，例如热力图、热力环、指标卡、节奏带、工具星系等。
- R6：将完整结论写入 `docs/research/wakatime-landing-data.md`，每项关键结论附可点击的一手资料链接；同时在对话中给出浓缩版表格与推荐。

## Acceptance Criteria

- [x] AC1：报告覆盖 WakaTime API 中与 Landing 有关的主要数据域，并说明 endpoint / 返回字段或聚合维度。
- [x] AC2：报告包含独立的 AI 能力矩阵，明确“原生可取 / 可由现有字段推导 / 当前不可取”。
- [x] AC3：报告至少提供一张数据能力表和一张展示方案表，展示方案说明适用指标、视觉编码、移动端退化及隐私处理。
- [x] AC4：报告给出一套推荐的 MVP 展示组合，以及至少一套更有表现力的进阶方案。
- [x] AC5：报告所有时效性与产品能力结论均由 WakaTime 一手来源支撑，并标注调研日期。
- [x] AC6：结论明确说明公开 Landing 应避免的字段和最小化公开策略。

## Out of Scope

- 实现 WakaTime OAuth/API Key 管理、后端缓存、共享 DTO 或前端组件。
- 访问用户的真实 WakaTime 账户或验证实际返回 payload。
- 设计完整的 Figma 稿或生产级视觉组件。
- 对无法由官方资料确认的 AI 模型、prompt、token、接受率或代码质量数据作猜测性承诺。
