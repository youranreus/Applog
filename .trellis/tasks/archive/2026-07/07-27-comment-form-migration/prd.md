# 重构评论框并增加评论迁移入口

## Goal

改善公开文章页的评论填写体验，并让管理员能够直接从评论管理页发起仅评论数据的远程迁移。

## Background

- 当前公开评论表单已经支持昵称、邮箱、个人站点和评论正文，但布局与期望不符。
- 当前系统已有 Typecho 远程数据库迁移能力及迁移配置界面，但评论管理页没有独立迁移入口。
- 本次迁移入口必须限定为评论资源，不迁移文章、页面、分类或其他数据。
- 现有后端已经支持 `resources: ['comments']`，并有测试保证该模式不读取或写入文章、页面。
- Typecho 评论通过 `typecho_comments.cid` 关联 AppLog 已迁移文章的 `extra.originalId`；找不到对应文章时跳过该评论并计入 `commentsMissingPost`，不会隐式迁移文章。
- 评论迁移使用 `(source, sourceId)` 保证幂等，重复执行默认只补充未迁移评论。

## Requirements

### R1 评论表单布局

- 「昵称」「邮箱」「个人站点」在评论正文上方同一行并列显示。
- 评论正文位于下方。
- 发送按钮悬浮在评论正文输入区域右下角，不再独立占据表单底部布局。
- 新的正文输入组件保持与项目 shadcn 输入控件一致的聚焦、禁用和校验视觉反馈。
- 现有评论提交、回复目标、访客信息记忆、校验、加载与禁用行为保持兼容。
- 窄屏下布局必须可用，不能因三列固定宽度或悬浮按钮造成内容遮挡。

### R2 评论管理页迁移入口

- 在后台评论管理页面的刷新操作旁增加「迁移」入口。
- 点击入口打开迁移弹窗。
- 弹窗复用现有迁移配置的远程库连接字段与交互模式。
- 从此入口提交的请求固定只迁移评论数据，不能由界面改选其他资源。
- 迁移采用幂等补充模式，不提供或发送 `clearExisting`，不清空任何现有评论。
- 迁移期间提供进行中状态，成功或失败后给出明确反馈；成功后刷新评论列表。
- 迁移接口继续受后台管理员权限保护。

## Acceptance Criteria

- [x] AC1：桌面宽度下，昵称、邮箱和个人站点在同一行，正文在下一行。
- [x] AC2：正文发送按钮位于输入区域内部右下角，输入文字和滚动内容不会被按钮遮挡。
- [x] AC3：正文组件的 focus ring、disabled、invalid 状态与现有 shadcn 控件风格一致，并支持现有表单交互。
- [x] AC4：移动端评论表单无横向溢出，身份字段与正文、按钮都可正常操作。
- [x] AC5：评论管理页刷新按钮旁可打开评论迁移弹窗，字段与原迁移连接配置一致。
- [x] AC6：评论管理入口发出的迁移请求只包含 `comments` 资源，不触发文章、页面或其他资源导入/清理。
- [x] AC7：迁移成功后显示结果并刷新评论列表；迁移失败时保留弹窗上下文并显示错误。
- [x] AC8：相关前后端类型检查、现有测试与新增针对性测试通过。

## Out of Scope

- 重做完整站点迁移页面。
- 新增 Typecho 之外的迁移源。
- 改变评论审核、回复、撤回或公开展示规则。
- 自动创建缺失的目标文章或迁移文章数据。
- 清空或覆盖现有评论。
