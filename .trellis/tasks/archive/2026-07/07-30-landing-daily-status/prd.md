# Landing 今日状态展示

## Goal

在 Landing 最近文章与最近运动之间增加「今日状态」区块，让访问者一眼看到站主截至当前时刻的整体状态、六项 Garmin 健康活动数据，以及与状态相呼应的动态 3D 小人。

## Background

- Landing 当前在最近文章后直接展示 Garmin 最近运动，新模块插入两者之间（`packages/frontend/src/pages/Landing/index.vue:84`）。
- Garmin worker 已按自然日写入私有 `garmin_health_daily`，并记录各数据域可用状态（`workers/garmin-sync/src/garmin_sync/repository.py:461`）。
- 生产核查发现最近 4 日的步数、静息心率、强度分钟和睡眠评分均未落库。步数与心率缺失源于 token 恢复后未初始化 profile，强度分钟源于字段别名错误；统一 daily summary 已验证能提供步数、目标、静息心率、强度分钟和最新身体电池。当前设备/账号不提供睡眠评分。证据见 `research/garmin-health-field-availability.md`。
- 公开 `GET /garmin/stats` 目前只提供最近运动。本功能需要新的严格白名单今日健康契约，禁止原样透传私有 `summaryData`（`packages/backend/src/module/garmin/garmin.controller.ts:17`、`.trellis/spec/backend/backend/garmin-guidelines.md`）。

## Requirements

### R1 — Placement and responsive layout

- 页面顺序为最近文章 → 今日状态 → Garmin 最近运动。
- 桌面端左右分栏：左侧程序化 3D 小人，右侧今日数据。
- 窄屏使用单列布局且无横向溢出；人物在上、数据在下。

### R2 — Four-level status evaluation

- 有效评估只输出「活得很好！」、「活得不错」、「活着」、「努力活着」四档之一。
- 采用透明、确定性的加权评分。输入为睡眠、身体电池、压力、步数完成率和强度活动；静息心率只展示，不在 MVP 中评分，避免脱离个人基线解读。
- 步数与强度活动按 Garmin 本地时区的当前时刻调整期望进度，晚间收敛到完整日目标；页面语义为“截至目前”。
- 缺失项不计零分；只对有效维度重新归一化权重。有效维度不足时显示「今日数据收集中」，不评级。
- 同一份快照、同一评估时刻必须得到同一结果；评分边界、时间进度和缺失策略必须由纯函数测试固定。

### R3 — Today metrics and goals

- 展示步数、今日静息心率、强度活动时间、平均压力、身体电池、睡眠六项。
- 步数和身体电池以进度条展示；其余为紧凑数据项。
- 步数目标优先级：站点后台配置 > Garmin 当日 `dailyStepGoal` > 默认 8,000。后台只允许合理正整数；公开接口只返回最终目标。
- 身体电池取统一 daily summary 的 `bodyBatteryMostRecentValue`，序列最新有效值为回退，范围 0–100；充入/消耗不作为主展示值。
- 睡眠优先展示 Garmin 睡眠评分；没有评分时降级为睡眠时长并按独立规则评分；两者都缺失时显示「—」且不参与评估。不得伪造 Garmin 分数。
- 公开 API 只返回六项展示值、有效步数目标、评估所需字段、自然日、更新时间和陈旧状态；不返回账号、原始 payload、位置或认证信息。

### R4 — Garmin reliability

- worker 使用依赖库的标准 token 恢复/profile 初始化流程，而不是只加载 token 字符串。
- 统一 daily summary 作为步数、目标、静息心率、强度分钟和最新身体电池的首选来源；独立 domain 作为补充或回退。
- 当日边界按配置的 Garmin IANA 时区计算，不得使用 UTC `date()` 代替本地自然日。
- 修复强度分钟真实别名 `moderateMinutes` / `vigorousMinutes`。
- 增加不含健康数值和身份信息的字段覆盖率/域失败可观测性，能发现字段长期为 null。

### R5 — 3D character

- MVP 使用基础几何、材质、灯光和分组关节组成程序化低多边形小人，不引入外部人物模型。
- 四档状态各有明显不同的循环动作；未评级使用中性待机动作。
- 动画不响应鼠标、点击或拖拽。
- 小人使用原生 CSS 3D 几何与透视，不引入外部模型或运行时依赖；尊重 `prefers-reduced-motion`，不支持 3D 变换时仍保持可读的静态人形，不阻塞数据展示。

### R6 — Loading, missing, stale and error states

- 模块始终保留页面位置；加载时显示骨架。
- 当日本地自然日没有快照时显示「今日数据收集中」，中性待机且不评级。
- 部分字段缺失时展示已有值，缺失项为「—」；只有达到最低有效评分维度数才评级。
- 超过 6 小时未成功更新时保留最后一份当日数值并标注「数据更新延迟」；不得使用昨日数据冒充今日。
- 接口错误使用轻量错误状态，不能影响最近文章或最近运动。

## Acceptance Criteria

- [ ] AC1：Landing 顺序为最近文章 → 今日状态 → 最近运动；桌面双栏、移动单列均无横向溢出。
- [ ] AC2：有效当日快照展示六项指标；步数和身体电池使用语义正确、可访问的进度条。
- [ ] AC3：目标步数严格按后台配置 > Garmin > 8,000 的顺序选择。
- [ ] AC4：固定快照和评估时刻稳定输出四档之一；缺失数据不计零分，维度不足不评级；早晨不会仅因全天步数/强度尚未完成而被系统性判差。
- [ ] AC5：睡眠评分不存在时显示真实睡眠时长，不伪造评分；两者都缺失时不参与评分。
- [ ] AC6：四档状态驱动四套自动循环动作；没有鼠标交互；减少动态偏好或不支持 3D 变换时静态降级可用。
- [ ] AC7：无数据、部分数据、超过 6 小时陈旧和接口错误均有明确中性展示，且不会展示昨日数据为今日。
- [ ] AC8：公开今日健康接口仅包含白名单字段；不泄露私有 payload、账号标识、位置或凭据。
- [ ] AC9：修复后的 worker 在结构测试中可归一化 daily summary 的步数、目标、静息心率、强度分钟和最新身体电池，并按 Garmin 本地自然日刷新今天/昨天。
- [ ] AC10：隐私安全的可观测性可以识别单字段连续多日缺失或 domain 失败，而不记录健康数值。

## Out of Scope

- 鼠标、触摸或游戏式 3D 互动。
- 外部/定制人物模型和模型编辑后台。
- 历史健康趋势、日期切换与状态回顾。
- 在公开 Landing 编辑目标或评分规则。
- 基于个人医疗阈值解释静息心率，或提供医疗建议。
- 替换现有 Garmin 最近运动模块。

## Risks and Deferred Items

- Garmin Connect 是非官方接口，字段可能漂移；通过白名单、回退来源、覆盖率监测和中性缺失状态控制风险。
- 当前账号没有睡眠评分，MVP 以睡眠时长降级；未来出现真实评分时无需改变公开指标槽位。
- 原生 CSS 3D 在旧浏览器会退化为平面几何，但数据内容与状态标签保持完整可用。
