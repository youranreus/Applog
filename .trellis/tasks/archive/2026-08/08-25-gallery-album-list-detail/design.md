# 相册列表与详情展示设计

## 体验方向

- **访客模式：Experience。** 相册封面和照片是视觉主角，界面仅提供必要的层级、返回路径和管理入口。
- `/gallery` 从长内容流变为稳定的封面卡片网格；固定卡片比例避免图片加载时布局跳动，8px 圆角与底部文字叠层延续当前照片 item。
- `/gallery/:albumId` 以轻量相册头部开场，随后让瀑布流占满可用宽度；不新增侧栏、卡片容器或装饰性阴影。
- 使用已有中性色、字体和交互组件。封面文字只增加保证可读性的底部渐变，不引入新的色彩体系。

## 页面与组件边界

### `Gallery/index.vue`：相册列表页

- 负责图库状态、相册摘要网格、相册卡片导航，以及管理员相册新建/编辑/删除 Dialog。
- 不持有照片列表、上传、照片预览或地图逻辑。
- 对空相册渲染占位封面；公开接口本身继续隐藏空相册。

### `Gallery/AlbumDetail.vue`：相册详情页

- 接收路由 `albumId`，加载图库状态与相册摘要，确认目标相册后只加载对应照片页。
- 负责相册头部、全宽瀑布流、游标加载更多、上传队列和照片预览入口。
- 无效或不可见 ID 显示不存在状态，不把 API 错误伪装成空相册。

### 页面局部组件

- 将全屏照片预览及照片编辑表单提取为 Gallery 页面局部组件，避免详情 SFC 再次膨胀，并保留 Teleport 所需的全局样式边界。
- 相册卡片若模板/交互足够简单可留在列表页；只有出现重复或明显复杂度时再提取，避免过度组件化。

### `useGallery.ts`：状态与业务逻辑

- `load()` 仅加载状态与相册摘要，不再遍历相册调用 `loadPhotos()`。
- 提供面向详情页的加载入口：加载摘要、解析当前相册、初始化并加载该相册照片。
- 动态照片状态写入 `reactive` record 后必须重新从 record 读取 Proxy；禁止把 `??=` 的原始右值继续交给异步请求修改。
- 相册变更只刷新摘要；照片上传、更新、删除只刷新当前相册照片及必要的摘要信息，不重新加载所有相册照片。
- 保留上传限制、并发数、游标追加和错误重试语义。

## 路由与导航

- 新增公开命名路由 `GALLERY_ALBUM`：`/gallery/:albumId`，置于通配页面路由之前。
- 相册卡片使用命名路由生成 URL；详情页返回 `/gallery`。
- 将相册详情加入现有返回按钮路由集合，使站点 Header 在详情层级提供一致的返回体验；页面内仍保留可理解的相册列表入口。
- 详情 SEO 使用响应式相册标题、描述、封面图与 canonical path。

## 数据流

```text
/gallery
  -> GET /gallery/status
  -> GET /gallery/albums (admin 使用 /gallery/admin/albums)
  -> 渲染 coverUrl 摘要卡片

/gallery/:albumId
  -> GET /gallery/status
  -> GET /gallery/albums (定位并显示相册摘要)
  -> GET /gallery/albums/:albumId/photos?cursor=...（仅当前相册）
  -> 打开照片时 GET /gallery/photos/:photoId
```

管理员使用对应 `/gallery/admin/*` 端点，客户端 DOM 隐藏不是权限边界，后端鉴权保持不变。

## 布局与响应式

- 相册列表采用移动优先响应式网格：默认 1 列、`640px` 起 2 列、`1100px` 起 3 列；卡片使用稳定横向比例，网格边缘遵循当前公共页面的宽屏留白。
- 详情照片区域 `width: 100%` 且无 `max-width`，使用小而明确的响应式页面 gutter；列 gap 与外部 gutter 形成统一节奏。
- 列表与详情共用 `calc(clamp(6.5rem, 10vh, 8rem) + env(safe-area-inset-top))` 顶部 gutter，与固定 Header 至少保留 24px；返回链接必须通过中心点命中和真实坐标点击验证，不能只断言 `href`。
- 瀑布流保留按宽高估算最短列的算法，断点仍为桌面 3 列、平板 2 列、移动 1 列。
- 图片使用显式宽高或比例、`loading="lazy"` 与 `object-fit: cover`；尊重 `prefers-reduced-motion`。

## 状态与兼容性

- 图库关闭：两个路由都显示原有不可用状态。
- 列表为空：管理员看到创建引导；访客看到暂无相册。
- 管理员空相册：详情显示上传第一张照片入口，列表显示无封面占位。
- 不存在/不可见相册：显示返回相册列表的不存在状态。
- 相册/照片请求失败：保留独立重试，不把已加载内容清空。
- 不做数据库迁移或后端发布顺序调整；回滚时可恢复旧单页与路由配置，API/数据不受影响。

## 契约与测试影响

- 更新 Gallery Cross-Layer Contract，把“同一公开相册页面管理”明确为“公开相册列表/详情层级中管理”，并记录列表不预取照片、详情单相册加载与全宽瀑布流。
- 更新前端契约测试，覆盖新路由、列表无照片加载、管理员能力跨页归属、详情瀑布流与预览契约。
- 生产检查包含 1440px、768px 和 390px 的可视验证、3/2/1 列数、两页等高顶部间距、横向溢出、卡片焦点、详情返回、全屏 Dialog 及加载更多。
